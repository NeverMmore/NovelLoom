# NovelLoom 小说织卡

SillyTavern（酒馆）UI 扩展：导入 TXT 小说，自动分段提取**章节大纲、角色档案、世界书条目、人物关系**，一键生成**角色卡**（含**群聊场景卡**）并写入酒馆（自动创建、绑定世界书）。另外可以让 AI **续写新章节**（续写内容会回灌资料库，支持**多视角管理**按角色切换文风、写完可做**连续性检查**）或**局部重写**某一段正文；写卡后写入酒馆前还能**试聊**几句看看立不立得住；也保留了在聊天里挂机续写的功能。

## 安装

任选一种：

1. **复制文件夹**：把整个 `NovelLoom` 文件夹放进
   `SillyTavern/public/scripts/extensions/third-party/`
   （多用户模式则放在 `SillyTavern/data/<用户名>/extensions/`），然后刷新酒馆页面。
2. **从 Git 安装**：把本文件夹推到你自己的 GitHub 仓库，在酒馆「扩展 → 安装扩展」里填仓库地址。

安装后有四个入口：扩展面板里的「🧵 NovelLoom 小说织卡」、输入框左侧魔杖菜单里的「小说织卡」（打开主界面）、同一个魔杖菜单里的「推演当前对话」（见下方「当前对话剧情推演」）、斜杠命令 `/novelloom`（可带参数，如 `/novelloom plan`）。

需要较新的酒馆（按 1.19 的接口开发；「连接配置档」模式要求启用酒馆自带的 Connection Manager 扩展）。

## 用法

| 步骤 | 页面 | 做什么 |
| --- | --- | --- |
| ① 导入 | 项目 | 选择 TXT 或粘贴文本。自动识别编码（UTF-8 / GBK / GB18030 / Big5 / UTF-16），按章节正则分段（每段默认 12000 字）。 |
| ② 提取 | 提取 | 逐段调用 AI，提取章节概要、角色档案、世界书条目、重要章节原文引用、文风、待确认名称。 |
| ③ 校对角色 | 角色 | 编辑档案（含人格颗粒度：绝对不会做的事/忌讳话题/口癖）、锁定字段、AI 整理、AI 别名检测与合并；「多选」批量删除或合并。 |
| ④ 梳理关系（可选） | 关系 | AI 分析已确立的人物关系，或手动添加/编辑；图谱可视化，接入角色卡「相关角色」。 |
| ⑤ 校对世界书 | 世界书 | 编辑条目、查找替换、快照回退、合并导入外部世界书，一键写入酒馆。 |
| ⑥ 调整文风（可选） | 文风 | 修改提取出的原著文风、加范文和禁用词，按任务选文风，或给需要独立视角的角色单独映射一种文风（多视角管理）。 |
| ⑦ 生成角色卡 | 角色卡 | 选角色、故事时间点、你的要求 → AI 写卡 → 本地审稿 → 写卡前试聊几句 → 写入酒馆（或导出 JSON / PNG）；也可以选多个角色生成群聊场景卡。 |
| ⑧ 写后续大纲（可选） | 写大纲 | 按你的要求规划接下来 N 章的大纲，可选拆到场次级；可编辑（含标记本章视角角色）、单章重写、从某章起重新规划。 |
| ⑨ 追伏笔（可选） | 伏笔看板 | AI 从各章大纲的「伏笔」字段整理出全书伏笔总表，看现在挂着几条没回收、埋了多少章；也可手动增删改。 |
| ⑩ 续写（可选） | 续写 | 按大纲逐章续写并回灌资料库，写完可做连续性检查；或选中一段用「AI 重写选中部分」局部调整；也支持在当前聊天里挂机续写。 |

### “续写”的两种含义都支持

- **滚动累积提取**（提取页 → 模式选“串行”）：每一段都会把前文已提取的角色档案和相关条目注入提示词，让 AI 在旧资料上补充、修正，而不是每段各记各的。选“并行”就是各段独立提取（最快，但重复较多；可以之后用 AI 别名检测合并）。“分批”介于两者之间。
- **AI 续写新章节**（续写页）：用大纲、角色档案、世界书和前文结尾续写。开启“回灌”后，每写完一章就立刻提取资料并合并进角色与世界书。

### 分卷模式（长篇推荐）

- **怎么分卷**：导入时自动识别“第X卷 / 第X部”标题（不同卷的章节不会被切进同一段）；也可以在「分段」页任意一段点“分卷”手动分卷、改卷名、取消分卷。
- **提取时**（提取页开启“分卷模式”）：只把**本卷**出现过的角色和条目列入“已知资料”（主要角色始终保留），并附上前几卷的**卷梗概**作为前情提要，提示词不会随全书变长而失控。
- **超限自动分卷**：接口报“上下文超限”时，自动从当前段开新卷并重试；也可以设一个 token 阈值，提示词预估超过就提前分卷。
- **卷梗概**：每卷结束自动生成（可关闭），也可在「分段」「大纲」页手动生成或编辑。卷梗概还会用在角色卡、写大纲和续写的剧情背景里。
- **分卷世界书**：「世界书」页可按卷查看、“分卷写入酒馆”（每卷一本「世界书名·卷名」）、“分卷导出”。可选“只含本卷出场的角色与条目”或“截至卷末的全部资料”。
- **条目版本**：每个世界书条目都记录各段之后的版本。按卷或按时间点生成世界书时，内容取当时的版本，后期才揭露的设定不会提前出现。

### 自定义消息链

设置页的“消息链”决定每次调用 AI 时发送哪些消息、各是什么角色（系统 / 用户 / AI）。默认是“系统提示 + 用户提示”。可以：

- 给所有任务设一条默认链，或给「分段提取 / 写角色卡 / 写大纲 / 续写正文 / 整理 / 推断待确认名称」等分别设置；
- 用占位符 `{SYSTEM}`（任务的系统提示）、`{PROMPT}`（任务的主提示）、`{BOOK}`（书名）；
- 加入破限、人设、示例对话，或在末尾放一条 AI 预填（如 `{`），预填内容会自动拼回回复开头；
- 每条消息可单独停用、上下移动，并预览最终发送的内容。

链里没有 `{PROMPT}` 时，会自动把主提示追加成最后一条用户消息，避免任务内容丢失。Gemini / Anthropic 直连时，开头的系统消息作为系统提示发送，中间的系统消息会转成带“[系统指令]”标记的用户消息。

### 写后续大纲

「写大纲」页根据已知内容规划后续章节：故事梗概与卷梗概、近期章节概要、主要角色现状、常驻世界设定、前文结尾、已有规划和此前的规划方向。你可以写明要求（剧情走向、节奏、必须发生的事件、要回收的伏笔、结局倾向），选择规划章数和每章详细程度。每章大纲包含章节名、概要、出场角色、关键事件、伏笔和章末钩子。

- 规划会接在已有规划之后；也可以“从此重规划”，用新要求替换某章及之后尚未写的大纲；
- 单章可以编辑、AI 重写（附修改要求）、插入、删除（后面章号自动顺延）；
- 章数多时分批生成（「每批章数」，默认 5；填 0 则一次写完）：每批单独请求，单次请求更短，不容易被 API 或网络中途断开；后一批会参考前几批已规划的章节，最后一批负责收束高潮与结局；某一批失败时已完成的批次会保留，再点生成会接着往后规划；
- 可导出 Markdown；
- 点“按大纲续写”，续写会逐章使用对应大纲：本章大纲写进提示词，后面两章大纲作为铺垫参考，写完自动标记“已写”；删除续写章节时对应大纲恢复为“待写”。

### 人物关系图谱

「关系」页梳理角色之间已经确立的关系，用来让扩写/续写更贴角色，也让角色卡的「相关角色」更准确。

- **AI 分析关系**：读取重要度最高的 20 个角色的档案，梳理出已经明确成立的关系（不推测尚未发生的关系），输出类型（爱慕/恋人、家人、朋友、师徒/上下级、同伴/盟友、对手/竞争、敌对、其他）、是否双向、一句话说明。按 (角色A, 角色B, 类型) 去重：已有的更新说明，没有的新增，重复分析不会产生重复记录。
- **手动编辑**：可以直接添加/编辑/删除一条关系，选角色、类型、是否双向、说明、备注、建立于哪一段（用于时间点筛选）。
- **图谱可视化**：环形节点布局，边按类型着色，单向关系带箭头；点节点或表格里的名字可以聚焦只看这个角色的关系；类型筛选、导出/导入 JSON。
- **故事时间点筛选**（防剧透）：和角色卡一样可以选“全书结束时”或某一段/卷末，只显示该时间点之前已经建立的关系。
- **接入角色卡**：生成角色卡时「相关角色」一节优先使用这里的明确关系，写清楚是谁、什么关系、一句话说明；剩余名额再用共同出场段/互相提及/重要度的启发式补齐。
- **自动同步**：角色改名、合并、删除，或所在的分段被删除/清空贡献时，指向该角色的关系会自动改名、合并去重或清除，不会留下断开的引用。

### 文风

「文风」页管理写作风格。一种文风包含：叙事视角、语言风格、情绪基调、写法规则（每行一条）、备注、范文片段、禁用词。

- **本书原著文风**：存在当前项目里。提取时自动填写视角/语言/基调（只填空白项，不会覆盖你改过的内容）；也可以点“AI 从原文提炼”，从全书均匀挑选片段，让 AI 总结出具体的写法规则和建议禁用词，确认后再应用。
- **文风预设**：存在插件设置里，所有项目通用。内置 5 个模板（轻小说风、古风武侠、网文爽文、严肃文学、第二人称沉浸式），可以直接改（改过的能“恢复默认”），也可以新建、另存、导入导出 JSON，或把某个预设复制到本书文风。
- **按任务选文风**：默认一种，角色卡 / 写大纲 / 续写可以各自指定，或选“不指定文风”。例如原著是第三人称，但角色卡想用第二人称沉浸式。
  - 角色卡：影响开场白和示例对话；勾选“文风”世界书条目时，条目内容也来自这里（不含范文）。
  - 写大纲：只用视角、基调、规则和备注，默认不带范文和禁用词。
  - 续写：全部都用。
- **范文片段**：可以粘贴其他作品的段落，也可以从原文里用鼠标选取，或自动挑选（全书均匀取对话与叙述兼有的片段）。范文会放进提示词，要求 AI 只模仿句式、节奏和对话写法，不照搬内容。注入的总字数有上限（默认 1500 字）。
- **禁用词**：每行一个，或用逗号、顿号分隔；`词=>建议` 给出替换建议；`/正则/` 匹配句式；`#` 开头是注释。可一键导入常见 AI 腔，也可以统计每个词在原文里出现了几次（原文常用的词不适合禁用）。另有全局禁用词，对所有文风生效。
  - 写进提示词，让 AI 提前避开；
  - 角色卡本地审稿会一并检查；
  - 续写每章写完自动扫描，命中后可以只提示、按建议自动替换，或让 AI 只改写命中的句子；续写页也能对单章手动“按建议替换”“AI 修正”。

### 局部重写

续写页「查看/编辑」对话框和分段页「查看」对话框里都有「✏️ AI 重写选中部分」：在正文里选中要改的一段，点这个按钮，说明修改要求（比如“加入更多环境描写”“让对话更冷淡一点”“删掉这句，换成更肯定的写法”），AI 只重写选中的部分，前后文原样保留、只用来保证衔接。重写会带上当前的文风设置，写完自动做一遍本地禁用词清理（能按建议替换的直接替换，替换不了的会在日志里提示）。适合不满意某一段但不想让整章重新生成的情况。

### 人格颗粒度与台词库

角色页「人格颗粒度」一栏补充三个字段，让扮演更稳：**绝对不会做的事**（硬底线）、**忌讳话题**（不主动提起）、**口癖/说话习惯**；每行一条，写卡时会一并交给 AI 参考。「原文对话样本」是从原文里抓取的真实对白（逐字校验，和「原文台词」共用校验逻辑），写卡时优先用来生成 `mes_example`，比纯 AI 编的示例对话更贴角色本来的说话方式。

### 写卡前试聊

角色卡列表每张卡都有「💬 试聊」：不写入酒馆、不消耗额外资料，直接用当前草稿卡片的 description / personality / scenario / first_mes / mes_example 拼一段扮演须知，在插件内跟这张卡聊几句，看看开场白接不接得住、语气对不对。对话只在对话框里临时保存，关闭即丢弃，不会污染酒馆聊天记录。

### 群聊/多人场景卡

角色卡页「群聊场景卡」：勾选至少两个已经确立关系的角色，说明这场戏发生的场合、{{user}} 的切入方式，AI 会设计一段可以把这几个角色放进同一个酒馆群聊的开场情境（`scenario`、旁白视角的 `first_mes`、每个角色在这场戏里的处境）。写入酒馆时会把这些角色**已发布**的卡拉进一个新建（或更新）的群聊，所以每个角色需要先在「角色卡」一节写入酒馆。也可以查看/编辑、复制 Markdown、删除（不影响酒馆里已创建的群聊）。

### 场次/节拍拆分

写大纲页勾选「拆分场次」后，AI 会把每章拆成 3–5 个场次（地点、在场角色、这一场发生的事），场次首尾衔接、按顺序写完就是这一章，比单纯一段「概要」更可控；章节列表和编辑对话框都能看到/改动场次（格式：`地点｜在场角色｜概要`，每行一条）。不开启则和之前一样，`scenes` 留空。

### 多视角管理

文风页「多视角管理」可以给需要独立叙事风格的角色单独映射一种文风（比如原著整体第三人称，但某个角色的番外想用第二人称沉浸式）。在写大纲页编辑某一章时把「本章视角」设成这个角色，续写这一章（以及对这一章「AI 重写选中部分」）就会优先用该角色映射的文风；没标记视角、或角色没有映射时，仍用「续写」任务的默认文风。POV 只能手动设置——AI 规划/重写大纲不会写这个字段，也就不会不小心把你设好的视角覆盖掉。角色改名/合并/删除时映射会自动同步清理。

### 伏笔看板

写大纲时每章都有「伏笔」一栏，但那只是散落在各章的自由文本，看不出现在总共挂着几条、哪条埋了很久还没回收——「伏笔看板」页把它整理成一张总表。点「🤖 从大纲整理」，AI 会读取各章大纲的「伏笔」字段，判断每一条是新埋下的还是已经在某章回收，按内容去重合并进总表（同一条伏笔只保留最新状态，重复分析不会重复累加）。也可以手动添加/编辑/标记回收/重新打开/删除，导出 Markdown 或 JSON（导入会合并去重，不会重复导入）。列表会提示现在挂着几条未回收、最久的一条已经埋了多少章。

### 连续性检查

续写章节「查看/编辑」对话框里的「🔍 连续性检查」：核对这一章正文有没有和已经建立的角色档案、世界设定打架——角色是否说出了这个时间点还不该知道的事、设定前后矛盾、言行违背既有性格、时间线不合理（比如已死或不在场的角色又出现）。核对用的「已知资料」会排除这一章自己刚回灌的内容（用回灌所在分段的前一段作为基准），避免拿这一章自己的剧透去验证自己、结果永远查不出问题。只指出有具体依据的矛盾，找不到问题就返回空列表，不会为了凑数硬找。

### 待确认名称：AI 推断名称

提取时，原文里只用模糊说法指代的对象（“那家店”“那位大人”）会记进「大纲」页的「待确认名称」。点「🎲 AI 推断名称」，AI 会读这一条出现处前后的原文片段（还会带上其他分段里提到它的地方，优先后文——真名常常在后面才揭晓）、已有角色和世界书条目、故事梗概，**每条一次给出几个候选**（默认 4 个，可选 2–6 个），并标出来源：

- **原文**：原文片段里出现过这个名字，附一句原文证据；
- **已有**：就是已有的某个角色或世界书条目；
- **AI 起名**：原文里找不到，AI 按本书的命名风格起的（对话框里取消「原文找不到时让 AI 起名字」就只给前两种）。

来源由插件本地核对，不只听 AI 的：说是原文但片段里找不到、说是已有但资料里没有的，会如实改标或去掉。点一下候选就填进确认名称，再点一下取消；AI 自动填入的（标着「AI 填入」）点一下高亮的候选就算确认（候选的理由和原文证据显示在下方，手机上不用悬停也能看到）。默认只把“原文里有 / 已有角色或条目”且把握大的候选自动填进空行，也可以选“都先填第一个”或“不自动填，只给候选”；手动填写或点选过的名称不会被 AI 改动，「全部重新推断」也一样。每行的「🎲 换一批」只为这一条要一批新的候选（不会重复之前给过的），已经填写的名称保留，它对应的候选仍排在最前面。

「把已填写的名称替换进资料」用法不变；如果其中有 AI 自动填入还没确认的、或 AI 起的名字，替换前会先列出来确认一次，替换前自动快照。条目多时分批请求（默认每批 6 条），某一批失败只记日志、不影响其他批，进行中可以停止，已完成的保留；推断进行中不能替换进资料，切换项目会停止推断。提示词「推断待确认名称」和对应的消息链可在设置页修改；导出 Markdown 大纲时会注明名称是否来自 AI。

### 故事时间点（防剧透）

生成角色卡时可以选“第 N 段结束时”或“某卷卷末”。卡片与绑定的世界书只使用该时间点之前的信息：角色的身份/性格/关系会回放到当时的状态，条目内容取当时的版本，之后才出场的角色和条目不会写进去。不同时间点的卡会绑定不同名字的世界书，互不覆盖。

### 写入酒馆时发生什么

1. 按「世界书命名」（默认 `《书名》世界书`）创建或覆盖同名世界书；
2. 导入角色卡，`extensions.world` 绑定到这本世界书，同时把世界书内嵌进卡片（导出分享时对方也能用）；
3. 默认不在世界书里重复写入该角色本人（资料已经在卡片描述里）；
4. 再次点击“更新到酒馆”会覆盖同一个角色，不会产生重复角色。

带状态栏的卡另外写入一本自己专用的世界书，见下一节。选了剧情导向、或 `{{user}}` 扮演原著角色 / 自定义身份的卡同样写入自己专用的「`世界书名·角色名`」（资料条目 + 本卡条目），见下面「卡的导向与 {{user}} 扮演」。同一个角色（或没填卡名、都叫书名的世界卡）有几张这样的卡时，排在后面的卡自动加上导向名或序号（如「`世界书名·莉莉丝·纯爱`」「`世界书名·莉莉丝·2`」），各写各的、互不覆盖；第一次写入后名字记在卡上，之后不变。

### 卡的导向与 {{user}} 扮演

- **卡名**：不采用 AI 写的名字。单人卡的名字就是角色名；世界/旁白卡用表单里填的「卡名」，留空时用书名（默认是导入的 TXT 文件名）。示例对话里以角色本名开头的台词会规整成 `{{char}}:`。
- **{{user}} 扮演**：原创新身份（默认）/ 原著角色（单人卡不能选卡片本人）/ 自定义一段身份。选原著角色时，写卡提示词会附上这个角色的简要资料（600 字以内），要求 AI 把指这个人的地方一律写成 `{{user}}`、原著里 `{{char}}` 和 TA 的关系就是和 `{{user}}` 的关系、不替 `{{user}}` 说话行动；世界卡的主要角色资料里不再列 TA；示例对话里这个角色的台词规整成 `{{user}}:`；状态栏 AI 设计「主角.*」变量时也按这个身份。卡自己的世界书里多一条常驻条目「`{{user}} 的身份`」，世界书资料里不再重复写这个角色。
- **卡的导向**：不限 / 内置 8 个（纯爱、NTL、NTR、后宫、百合、耽美、虐恋、日常）/ 我的模板 / 自定义（只用这一次，填名称和说明）。选了导向时写卡提示词里多一段导向说明和写卡要求；勾选「让 AI 结合本书细化导向词条」（默认勾选）时 AI 另外写 3-6 行**本书落点**（例如谁是原伴侣或第三者、关键阻碍是什么）。卡自己的世界书里多一条常驻条目「`剧情导向：名称`」（正文 + 【本书落点】），默认插在聊天深度 4、系统角色。
- **编辑**：卡片「编辑」里的「剧情导向」一节可以换导向、改词条正文和本书落点，🎲「重新生成本书落点」只让 AI 重写落点（可附加要求）。换成「不限」后再写入酒馆，条目会从这本世界书里去掉。
- **导向模板**：写卡表单的「管理导向模板」或设置页「卡的导向模板」：内置模板只读，可以复制成自己的再改；我的模板可以改名称、说明、写卡要求、词条正文和插入深度 / 消息角色 / 顺序，导入导出 JSON，存在扩展设置里所有项目共用，随配置导出导入。

### 状态栏 / MVU 变量

写角色卡时勾选「写卡选项 → 同时生成状态栏（MVU 变量）」（默认不勾选），写完卡后 AI 会接着为这张卡设计一套随剧情变化的变量（时间地点、好感、心情、着装、物品……），以及显示在每条 AI 回复下面的状态栏。已经写好的卡也可以在卡片列表点「状态栏」再生成。导出的卡基于社区通用的 [MVU（MagVarUpdate）](https://github.com/MagicalAstrogy/MagVarUpdate) 变量框架和 StageDog 的 mvu_zod 变量结构写法：AI 每次回复末尾输出一段 `<UpdateVariable><JSONPatch>…</JSONPatch></UpdateVariable>`，MVU 解析后更新变量，状态栏跟着刷新。

**生成了什么**（AI 只写变量表和界面，其余都由 NovelLoom 按变量表编译，不让 AI 写脚本）：

- **变量表**：路径（如 `莉莉丝.好感度`，最多 3 层）、类型（数字 / 文本 / 选项 / 是否 / 列表 / 记录）、初始值、范围或选项、显示方式、检查规则；默认最多 12 个变量。
- **两个酒馆助手角色脚本**（`extensions.tavern_helper`，已启用）：「MVU」加载 MVU 框架；「变量结构」是按变量表生成的 zod 结构，每个变量都带初始值，世界书没导入时也能得到完整的初始状态。
- **本卡专用世界书**「`世界书名·角色名`」：资料条目（开着绑定或内嵌世界书时）+ 四个状态栏条目——`[initvar]变量初始化勿开`（初始值，禁用状态，MVU 照样读取）、`变量列表`、`[mvu_update]变量更新规则`、`[mvu_update]变量输出格式`。这本世界书总是写入酒馆并绑定、同时内嵌进卡片，即使没开「绑定世界书」（MVU 只从角色绑定的世界书读初始值）；第一次写入后名字记在卡上，在「编辑」里可以改。
- **局部正则**（`extensions.regex_scripts`，5 条；关掉「折叠变量更新块」时 3 条）：在回复里显示状态栏、发给 AI 前去掉占位标签和历史里的变量更新块、把聊天里的更新块折叠成可展开的小块。
- **开场白**和每个备选开场白末尾加上 `<StatusPlaceHolderImpl/>`，开场就能看到状态栏；作者备注里附一段使用说明（可关）；`extensions.novel_loom.statusBar` 保存变量表和界面，方便以后导入成模板。

**状态栏对话框**（卡片列表或「编辑 → 更多字段」里的「状态栏」）：

- **变量**：表格或 JSON 编辑，即改即存；不合法的行标红并写明原因（不生效）；显示每轮常驻的 token 估算。可以「AI 重新设计」。
- **规则**：每个变量的检查规则；编译出的更新规则 / 输出格式 / 初始值预览；变量分析（`<Analysis>`）用英文（默认，省 token）或中文；发给 AI 的历史里保留最近几轮更新块；高级选项可以手动覆盖编译结果（覆盖后**不再与变量表同步**）。
- **界面**：三种方式——**AI 设计**（AI 只写样式和带 `data-nl-*` 绑定的标记，读取变量和刷新由 NovelLoom 的运行时负责）、**内置排版**（不调用 AI，3 种配色）、**自定义 HTML**（粘贴社区状态栏那种完整页面）。界面代码会被检查：`$1` 这类 `$` 加数字、`{{…}}` 宏（`{{user}}`/`{{char}}` 除外）、三个连续的反引号、`<user>` 这类旧占位符会在酒馆正则替换时把界面改坏，属于错误，**有错误时导出和写入酒馆都会被阻止**；外部图片、`vh` 单位之类只是提醒。显示在哪些回复上可选「只最新一层」（默认）/「最新 N 层」/「每一层」，按 AI 回复计。
- **预览**：沙箱 iframe 里模拟酒馆助手和 MVU，显示的内容和导出到酒馆的完全一致；可以改示例变量、换成初始值或随机值，或粘贴一条带 `<UpdateVariable><JSONPatch>` 的 AI 回复「模拟一轮更新」（不合法的更新会被丢弃并说明原因）；手机 375 / 宽屏 720，深色 / 浅色背景。
- **导出**：只读的正则、脚本、世界书条目 JSON（可复制），以及环境检查：酒馆助手版本、本卡正则是否已允许。
- 顶部：导出时带不带状态栏的开关、全部重新生成、存为模板、模板库、撤销（撤销上一次 AI 生成或套用模板，再点一次恢复）。
- **模板**：内置「通用」「RPG」「校园恋爱」「赛博朋克」「多人群像」五个模板（只读，可以复制成自己的再改），也可以把当前状态栏存成模板、导入导出模板 JSON，或从带状态栏的角色卡 JSON 导入。套用时选**沿用结构**（照搬变量表和界面，AI 只按这张卡填初始值和规则）或**只借外观**（保留本卡变量，AI 参照模板的风格重写界面）。写卡表单里也可以直接选模板。模板存在扩展设置里，所有项目共用，设置页「状态栏」一节也能管理。
- 整卡重新生成会沿用原来的状态栏并标为「过时」，可以在对话框里让 AI 只更新初始值。

#### 多人状态栏：世界卡、分组字段、立绘

- **世界/旁白卡也能带状态栏**：写世界/旁白卡时同样可以勾「同时生成状态栏」，卡片列表里也有「状态栏」按钮。这时 `{{char}}` 是旁白，AI 为整个群像设计变量：
  - 「主要角色」记录：键是角色名，每个角色一套字段。生成后 NovelLoom 会把项目里到这张卡时间点为止出场的主要角色补进初始条目，AI 已经写了的保持原样。
  - 「NPC」记录：开始是空的，扮演中由 AI 用 `insert` 加入新出场的人，离开后用 `remove` 删掉。
  - 再加上 `世界.时间`、`世界.地点` 这类共用变量，以及 `主角.*`（你自己）。

  世界书、正则、脚本、开场白标签都和角色卡一样，世界书名是「`世界书名·卡片名`」。变量表里记录那一行有「填入主要角色」按钮，可以随时把项目里的主要角色补进去。两段提示词（「状态栏 · 变量表 / 界面 · 世界卡附加说明」）可以在设置页的「提示词模板」里修改。
- **分组字段**：记录的每个条目除了普通字段，还可以有一层分组，例如 服饰（上衣 / 下装 / 配饰）、状态（心情 / 心理活动）。
  - 限制：每条记录最多 8 项（分组算一项），每组最多 6 个字段，分组里不能再分组。
  - 变量数按字段算：每个字段算一个变量，和记录里有多少条目无关。
  - 更新路径一直写到分组里的字段，例如 `/主要角色/莉莉丝/服饰/上衣`。zod 结构、初始值 YAML、更新规则（会列出示例路径）、预览和模拟更新都支持分组。
  - 编辑：变量表里记录那一行下面有字段编辑器，可以添加字段、添加分组、在分组里添加字段、上下移动、删除，有问题的项就地标红。原来的 JSON 编辑框收在下面。
  - 显示：界面里用 `data-nl-item="服饰.上衣"` 显示单个字段，`data-nl-group="服饰"` 把整组逐个字段列出来。内置排版把分组显示成子区块。
- **立绘**（对话框的「立绘」分页；你自己配置，不由 AI 生成，图片地址也不会发给 AI）：
  - **每个角色一组图**：角色可以是记录里的条目名、`主角` 这类固定分组，或你自己填的名字。每张图有地址（本地图片、http/https 图床地址，或 `data:image`；不支持 svg）、可选的说明和**解锁条件**。解锁条件例如「好感 ≥ 60」，路径相对这个角色的条目，也可以写完整路径（如 `主角.声望`）。默认显示已解锁的图里排在最后的那张。
  - **图池**：给一个记录（如 NPC）按一个字段（如 阵营）配几组图。没有自己图片的条目按这个字段的值从对应的组里取一张，按名字固定挑选，刷新也不会变；没有对应的值时用兜底图。
  - **在状态栏里**：带 `data-nl-portrait` 的位置显示立绘。**换一张**按钮（`data-nl-portrait-next`）只在已解锁的图之间轮换，不足两张时自动隐藏。手动选的图记在玩家浏览器的本地存储里（键 `nl-sb:卡片id:名字`），换回默认那张就不再记着。没有图或图片打不开时显示名字首字的占位块。
  - **在预览里**：也能点换一张，换过的图会记住，重新载入预览后仍是选的那张。这份记录和酒馆聊天里同一张卡共用。预览只能记下（或换回默认）它正在显示的角色的选择，地址也必须是这张卡配置的立绘；每张卡最多记 200 条。
  - **编辑时的提示**：缩略图实时检查地址，打不开或地址不合法时标红，标红的不保存。每张图会按预览的示例数据标出「默认显示」「未解锁」。当前界面不会显示立绘时会提醒（自定义 HTML，或 AI 设计的界面里没有立绘位）。
  - **选择本地图片**：每个角色、图池的每个取值和兜底都有「选择本地图片」（可以多选，也可以直接把图片拖上去；超出每组 12 张的会跳过并列出）。分页顶部选之后选的图默认存到哪儿（记在扩展设置里，所有卡共用；已经加进来的图不会跟着变）：
    - **酒馆服务器**（默认）：上传到酒馆的 `user/images/卡片名/`，也就是这个角色的「图库」。不限大小、卡片不变大；4MB 以内、最长边不超过 2048 的 png / jpg / gif / webp / bmp 原样上传（GIF 动图照样会动），其余转成 webp（最长边 1600，太大的 GIF 因此只留第一帧，会提示）。文件名是内容哈希，同一张图只存一份。**把卡分享给别人时这些图不会跟着走**，对方只看到首字占位。
    - **嵌进卡片**：缩到最长边 512 的 webp（质量和尺寸自动往下调，直到每张不超过 128K 字），随卡分享，但卡片会变大，合计最多 768K 字（顶部有用量）。
    - 每张图下面标着它存在哪儿（图床 / 酒馆 / 内嵌 + 大小），「改成内嵌」「存到酒馆」可以随时互换，说明和解锁条件不变；图池的一组图可以「全部改成内嵌 / 全部存到酒馆」，每张缩略图上的 × 删掉文本框里对应的那一行。上传失败（连不上酒馆、登录过期、酒馆报错）会就地说明原因，可以一键改成嵌进卡片。一次只处理一批图，处理中再点会请你稍等。删掉的图不会从酒馆服务器上删除，仍在这个角色的图库里。
    - 也可以直接填图库里已有图片的路径（如 `/user/images/角色名/xxx.png`），中文、空格、`@` 等会自动换成编码后的写法。
    - 有立绘存在酒馆服务器上时，「立绘」「导出」分页、导出 JSON / PNG 时都会提醒；「立绘」页顶部的「全部改成内嵌」一次把它们都嵌进卡片（内嵌合计放不下的留在服务器上并说明）。
    - 预览在沙箱里运行，可能带不上酒馆的登录信息：NovelLoom 先把自己上传到酒馆服务器的立绘取来再给预览显示（手填的其他图库路径不替它去读，开了账号登录时预览里可能显示不出来），卡片和导出里仍是原来的地址；聊天里由酒馆助手直接加载。
- **「多人群像」模板**：为世界/旁白卡设计。
  - 顶栏显示时间、地点和主角身份，下面是「主要角色 / NPC」两个分页。
  - 每个分页是角色卡片网格：立绘位和换一张、心情、五段好感条（按阶段着色）、阵营。
  - 点开卡片看详情：基础、状态（含心理活动）、服饰分组。按 Esc 或点空白处关闭。
  - 没有配立绘时显示带首字的占位图。
  - 共 15 个变量，模板自带上限 15：设置里的变量上限低于 15 时（例如旧版默认的 12）套用也全部保留，变量表也按 15 校验。套用到世界卡并让 AI 按这张卡调整时，主要角色会被补进「主要角色」。
- **模板与立绘**：
  - 存为模板时可以勾「连同立绘设置」，默认不勾，因为图片地址是你自己的。模板存在扩展设置里，内嵌图片的上限更小（每张 32K、合计 192K 字），超出的存模板时会去掉。酒馆服务器上的图不随导出的模板走，512px 的内嵌立绘通常又超过模板的上限：要分享模板请用图床地址，只在本机用可以存到酒馆服务器。
  - 从带立绘的 NovelLoom 卡片 JSON 导入模板时会带上立绘。
  - 套用带立绘的模板时，立绘并进卡片已有的立绘（同名角色以卡片自己的为准）。撤销时一起换回。

**设置页「状态栏」一节**：MVU 与 mvu_zod 的脚本地址（默认 testingcf.jsdelivr.net 镜像、不固定版本，可改）、变量上限（3–100，默认 20；以前保存过的值不变。变量越多，每轮发送的规则和 AI 输出的更新就越长）、「写入酒馆后自动允许本卡的局部正则和角色脚本」（默认开）、新状态栏默认用 AI 设计还是内置排版、内置排版配色、分析语言、显示层数、保留几轮更新块、折叠更新块、开场白显示状态栏、附使用说明。状态栏的 AI 调用可以在「消息链」里单独设置（任务「状态栏（变量/界面）」），提示词在「提示词模板」里可改。

**在酒馆里使用的要求**（写入酒馆后会弹出提示）：

1. 安装**酒馆助手（JS-Slash-Runner）4.6 或更高版本**；
2. 使用**聊天补全（Chat Completion）**接口；
3. **允许本卡的局部正则**（默认在写入酒馆时自动替这张卡加进酒馆的允许名单；关掉设置页「状态栏」一节的「写入酒馆后自动允许」后，酒馆第一次打开这个角色时会询问，提示框里也有「允许本卡正则」按钮）；
4. **允许本卡的角色脚本**（默认在写入时自动在酒馆助手里启用本卡脚本，不再弹窗询问；找不到酒馆助手的设置界面时改写它保存的设置，日志会提示刷新酒馆页面后生效；关掉自动允许时酒馆助手第一次打开会询问，拒绝过的话到 酒馆助手 → 脚本库 → 角色脚本 里启用）；
5. 分享出去的卡被别人导入时，要选择**导入内嵌世界书**，否则只有初始值，没有变量更新规则。

用「更新到酒馆」覆盖同一个角色时，正则和脚本的授权都会保留（酒馆按头像文件记录）。

已验证版本（按这些版本的源码核对了卡片、正则、脚本与世界书的格式）：SillyTavern 1.19.0 / 酒馆助手 4.11.3 / MVU 0.190.0 / mvu_zod 0.3.453。

## 防截断

设置页的「防截断」一节处理回复写到一半断掉的情况：

- **自动接续**：回复因长度上限被截断时，自动让 AI 从断点接着写并拼好（默认最多接续 3 次），续写正文、角色卡、提取、写大纲都适用。直连接口按服务商返回的结束原因判断；酒馆当前连接和连接配置档拿不到结束原因，改为检查正文是否停在半句、JSON 是否没有闭合。接续方式可选“预填”（把已写内容作为 AI 消息让模型直接接着写，Claude 直连默认用这个）或“追问”（再发一条“从断点继续”的消息，其余接口默认用这个），提示文字可改。
- **服务商过滤**：Gemini 的 SAFETY / PROHIBITED_CONTENT、OpenAI 的 content_filter 等会单独提示“被服务商拦截，不是长度截断”，不会反复接续或重试。Gemini 直连可在接口设置里选安全阈值（BLOCK_NONE / OFF / BLOCK_ONLY_HIGH / 服务商默认），这是 Gemini 官方提供的参数。
- **模型拒绝**：短回复开头是拒绝用语时直接提示，不做无效重试。

酒馆当前连接的回复长度取酒馆里的“最大回复长度”，写长章节前建议调大，能减少接续次数。你自己的预设提示词可以放进「消息链」，插件会原样发送；连接配置档模式也可以勾选“使用配置档里的采样预设”。

## AI 接口

| 模式 | 说明 |
| --- | --- |
| 酒馆当前连接 | 最省事，用酒馆当前的 API 和模型。回复长度沿用酒馆里的“最大回复长度”，建议调到 4000 以上。提示词里给 AI 看的 `{{char}}` / `{{user}}` 会原样发出（插入零宽空格防止酒馆把它们换成当前打开的角色名和用户名，回复里再还原）。 |
| 酒馆连接配置档（推荐） | 通过酒馆后端转发，不受跨域限制，密钥由酒馆保管，可以并行、可以单独中止。先在酒馆「连接配置档」里存一个配置。 |
| OpenAI 兼容 / Gemini / Anthropic | 浏览器直连，需要填地址和密钥。部分服务商会因跨域（CORS）拒绝，这时改用连接配置档。 |
| DeepSeek（官方接口） | 浏览器直连 DeepSeek 官方 API，本质是 OpenAI 兼容模式的预设：地址/模型留空会自动填官方默认值（`deepseek-chat` / `deepseek-reasoner`）。`deepseek-reasoner` 返回的思考过程（`reasoning_content`）会自动和正文分开，不会混进卡片或 JSON 输出，收到后会在日志里提示一行。 |

续写可以单独指定一个接口（比如提取用便宜快速的模型，续写用文笔好的模型）。

## 功能清单

- **导入与分段**：编码自动识别；章节正则预设 + 自定义；超长章节按段落/句末切分；目录行与短序言自动并入，不丢字；分段查看/编辑（含 AI 重写选中部分）/合并/删除/从某段开始提取/单段重新提取（可附加要求）。
- **提取**：串行 / 分批 / 并行；已知资料注入上限可调；AI 输出 JSON 容错（代码块、尾逗号、未转义引号、截断、思考标签）；解析失败自动要求重输；失败自动重试（429/5xx/超时，指数退避）；暂停/停止/断点续跑；只重试失败段；**重新提取**（全部 / 从第 N 段起 / 分段页多选，先清掉这些段的旧资料、自动快照，快照可回退资料与分段状态）；提示词预览；自动快照；提示词禁止用拼音/注音替代汉字，并本地扫描提取结果里的注音符号，命中记入「大纲」页待核实列表（见下）。
- **角色档案**：姓名、别名、性别、年龄、身份、性格、关系、外貌特征、能力、经历（带段号）、原文台词（逐字校验）、**人格颗粒度**（绝对不会做的事/忌讳话题/口癖）、**原文对话样本**（逐字校验，写卡时优先喂给 mes_example）、**AI 扩写**（🎲 把已有档案写得更细致，可附加要求）、**NSFW 补充资料**（独立区块，跟日常资料分开存放，生成角色卡时可选是否带上）、变化记录（按段回放）、重要度、锁定、条目配置。
- **世界书**：自定义分类（提取指南、🔵常驻/🟢关键词、位置、深度、顺序、自动递增）；默认条目；“剧情大纲”“文风”附加条目；AI 整理长条目；AI 别名合并；查找替换（支持正则）；修改历史快照与回退；预览最终条目与 token；导出 ST 格式 JSON；合并导入外部世界书或角色卡内嵌世界书。
- **大纲**：AI 故事梗概、文风概览、章节概要编辑、重要章节与原文引用、待确认名称（**AI 推断名称**：每条一次给几个候选并标明来源——原文 / 已有 / AI 起名，点选填入、换一批；填好后一键替换进资料）、**疑似敏感词被替换成拼音/注音提醒**（本地扫描，点「核实」跳到对应分段核对原文）；导出 Markdown 大纲、角色档案 TXT。
- **写大纲**：按要求规划后续章节；单章编辑/AI 重写/插入/删除/从某章起重新规划；**可选拆分到场次级**（地点/在场角色/概要）；**可标记本章视角角色**（配合多视角管理）；导出 Markdown。
- **角色卡**：单人角色卡 / 世界·旁白卡（卡名可填，留空用书名；卡名不采用 AI 写的名字）；故事时间点；你的要求 + 默认要求；**{{user}} 扮演**（原创新身份 / 原著角色 / 自定义，写成卡自己世界书里的「{{user}} 的身份」）；**卡的导向**（内置 8 个 + 我的模板 + 自定义，AI 结合本书细化【本书落点】，写成卡自己世界书里的常驻「剧情导向」条目，编辑里可换导向、🎲 重新生成本书落点）；**生成表单里先选封面图，生成时直接带上**；备选开场白数量与长度；字段编辑与 token 计数；本地审稿（破折号、模糊词、八股微表情、陈旧比喻、主观评价、情绪宣告、占位符等）；AI 按审稿意见修正；**整卡重roll，或点字段旁的 🎲 只重新生成这一个字段（可附加要求）**；头像上传/替换；**写入酒馆前试聊**；**剧情推演**（根据卡片当前内容 + 相关世界书，先给几个并列走向，勾选一个或几个后再推演出具体的分阶段发展，可编辑/增删/导出 Markdown，不会自动改动卡片本身；**干预走向**——生成前可以给每一条走向单独写方向提示，留空的条目不限方向由 AI 自由发挥，重新生成时默认带入上次各条走向的标题方便只改一条；方向提示可以**存成模板**，保存在插件设置里、所有项目通用，套用模板时由 AI 结合这张卡的具体设定重新展开，不是原样照抄）；写入酒馆 / 导出 JSON（V3）/ 导出 PNG（内嵌 chara + ccv3）。
- **状态栏（MVU 变量）**：写卡时可同时生成（默认不勾选）；AI 设计变量表与状态栏界面，NovelLoom 编译出 MVU 与变量结构两个酒馆助手角色脚本、本卡专用世界书（初始值 / 变量列表 / 更新规则 / 输出格式）、5 条局部正则和开场白占位标签；变量表格/JSON 编辑、检查规则、手动覆盖；界面三种方式（AI 设计 / 内置排版 / 自定义 HTML），界面错误阻止导出；沙箱预览与模拟一轮更新；显示层数（最新 1 层 / N 层 / 每一层）；5 个内置模板（含为世界卡设计的「多人群像」）+ 自己的模板（沿用结构 / 只借外观，导入导出，可带立绘与自带变量上限）；**多人状态栏**：世界/旁白卡也能带状态栏（主要角色 / NPC 记录，主要角色按项目自动补齐）、记录里的分组字段（服饰：上衣 / 下装 / 配饰……）、立绘（选择本地图片，存到酒馆服务器或压缩后嵌进卡片；解锁条件、按字段取图的图池、换一张并记住选择、首字占位）；一步撤销；写入酒馆时自动允许本卡的局部正则并在酒馆助手里启用角色脚本（可在设置里关掉，关掉后提示框里一键允许本卡正则）；变量上限 3–100（默认 20）。需要酒馆助手 4.6+。
- **群聊/多人场景卡**：勾选两个以上已确立关系的角色，AI 设计一段可放进同一场戏的开场情境（scenario/first_mes/各角色处境）；查看/编辑、复制 Markdown、写入酒馆时创建或更新群聊并拉入已发布的角色。
- **文风**：本书原著文风 + 文风预设（5 个内置模板）；按任务选择；**多视角管理**（按角色单独映射文风，写大纲标记视角后续写/局部重写自动切换）；范文片段（粘贴 / 原文选取 / 自动挑选）；禁用词（替换建议、正则、全局禁用词、原文出现次数统计）；AI 提炼文风；导入导出。
- **人物关系图谱**：AI 分析已确立的关系（类型、是否双向、一句话说明，按角色对+类型去重）；**关系类型自由填写**（内置 8 种和自定义类型只是参考，AI 和你都可以直接写更贴切的短类型，如 师兄妹、青梅竹马、主仆，最多 8 个字；写的正好是已知类型的名字时归到那个类型；自由类型的颜色按它像哪一类来配，归不了类的按文字固定一个颜色；筛选、图谱下的图例只列项目里实际用到的类型，点图例也能筛选）；**自定义关系类型**（可增/改名/改色/删除，保存在扩展设置里所有项目通用，和内置类型合并使用）；**关系模板**（类型 + 单/双向 + 说明写法，{A}/{B} 代表两个角色，添加/编辑关系时一键套用，「AI 分析关系」时写进提示词让 AI 优先按模板归类；随配置导出导入）；手动增删改；环形图谱可视化（按类型着色、单向箭头、点节点/名字聚焦）；类型与故事时间点筛选（防剧透）；导出导入 JSON；接入角色卡「相关角色」；角色改名/合并/删除时自动同步。
- **伏笔看板**：AI 从各章大纲的「伏笔」字段整理成总表（识别新埋下/已回收，按内容去重合并）；手动增删改、标记回收/重新打开；提示未回收数量与最久挂了多少章；导出 Markdown / JSON，导入合并去重。
- **续写**：API 续写（章数、字数、方向、前文参考字数、是否参考世界书、是否回灌，可按视角自动切换文风）；写完扫描禁用词并可自动替换或 AI 改写；**连续性检查**（AI 核对正文与已知设定是否冲突，核对基准排除这一章自己回灌的内容）；续写章节查看/编辑/删除（删除时连同回灌的资料一起清除）；**整章 🎲 重新生成**（沿用原方向，已回灌的分段自动标记为待重提）；**AI 重写选中部分**（选区局部重写，前后文保持不变，自动本地禁用词清理）；导出续写 TXT 或原文+续写。
- **聊天挂机续写**：目标章数、提示词、回复等待、稳定检测、弹窗检测、最小字数、失败重试、每 N 章自动导出、断点续传、可把每章回复加入项目；聊天导出 TXT/JSON（楼层范围、用户/AI、原始内容、标签白名单/黑名单）。
- **项目**：多项目，数据存在浏览器 IndexedDB；导出/导入任务文件（跨设备恢复）；导出/导入配置（默认不含密钥）；窗口可最小化，任务在后台继续。
- **当前对话剧情推演**：和上面角色卡页的「剧情推演」是两条独立的路——这个不需要打开 NovelLoom 项目，直接从魔杖菜单点「推演当前对话」，基于**正在聊的这个单人角色对话**（角色卡当前的实际字段 + 目前为止真实的聊天记录 + 这个对话当前会触发的世界书条目）推演接下来可能怎么走；交互方式和角色卡页一致：先给几个并列走向（可干预方向、存成模板，和角色卡页共用同一套模板池），勾选后再推演分阶段发展，可编辑/增删/导出 Markdown。结果存在**这个对话自己**的聊天数据里，换一个对话或角色互不影响，也不会改动角色卡本身；群聊暂不支持。

## 已知限制

- 并行/分批模式下，同一角色的身份、性格以“分块顺序最靠后”的结果为准，前后矛盾时请在角色页校对或用“AI 整理档案”。
- 条目版本最多保留 30 个；手动编辑条目只改最新版本。
- 酒馆当前连接模式下，停止任务会调用酒馆的停止生成（会同时停掉聊天里正在进行的生成）。
- 浏览器直连第三方接口可能被 CORS 拦截，改用连接配置档即可。
- 文风预设保存在酒馆的扩展设置里（随酒馆设置同步）；本书原著文风保存在项目里，随任务文件导出。
- 酒馆当前连接 / 连接配置档没有结束原因，截断靠内容判断：正文以非标点结尾会被当作截断去接续（模型回复 [END] 时停止），极少数情况下会多一次调用。
- 禁用词按字面匹配，不区分语境；“AI 改写”会把整章发给模型，长章节会消耗较多 token。
- 数据保存在当前浏览器的 IndexedDB，换浏览器或清理站点数据前请导出任务文件备份。
- “AI 分析关系”只读取重要度最高的 20 个角色的档案，次要角色之间的关系需要手动添加。
- 局部重写不会把结果回灌进提取资料库（章节概要、角色档案等仍是重写前的版本），改动较大时建议之后用「重提」或「AI 整理档案」同步。
- 台词库（原文对话样本）由提取时 AI 顺带给出（每段每个角色 0–2 段），逐字校验，最多保留最近 12 条；界面目前只能删除，不能手动新增一条。
- 伏笔看板依赖各章大纲的「伏笔」字段：字段写得越具体（谁的什么事/什么物件），AI 整理出的总表越准；大纲阶段没写伏笔的章节不会被看板收录。
- 连续性检查只核对“已知设定”和正文是否冲突，不检查文笔或情节合理性；判断依据来自角色档案和世界书条目，没建档的细节它查不出来。
- POV（多视角管理）只能手动在写大纲页设置，AI 规划/重写大纲不会自动填写或修改这个字段；章节大纲删除/插入导致章号变动时，伏笔看板里记录的「埋下/回收章号」不会跟着重新编号。
- 敏感词替换检测只识别输出里混入注音符号（ㄅㄆㄇㄈ）的情况，查不出被换成拼音字母、同音字或直接删字的替换；原文本身就包含乱码（如源文件编码错误）也可能被误判为这类替换，请去分段里核对原文再决定怎么改。
- 删除自定义关系类型后，已有关系的 `type` 字段不会自动改成别的类型，只是图谱/列表里显示会退回「其他」；需要的话手动把这些关系改成别的类型。
- 续写页整章 🎲 重新生成只把已回灌的分段标记为「待重提」，不会自动重新提取——需要去「分段」页手动点「重提」才会更新章节概要/角色档案等资料。
- DeepSeek 的 `reasoning_content`（思考过程）只在日志里提示一行字数，不会展示完整内容；确实需要看思考过程原文的话目前只能去接口方自己的后台查。
- 剧情推演完全独立于「写大纲」的后续章节计划，两者不互相同步；结果也不会自动写回角色卡的 description/scenario 等字段，需要的话自己手动摘录。
- 重新生成走向会清空当前的选中状态，但不会自动清空已经生成的分阶段推演（避免误删已编辑过的内容）；如果走向改了，记得自己重新推演或删掉旧的分阶段结果。
- 走向模板存的是「大方向点子」（标题+简短说明），套用时会由 AI 结合这张卡的具体设定重新展开，不是把模板文字原样当成走向插入；模板保存在插件设置里，所有项目共用，改名/查重只在这个全局列表里判断，不区分项目。
- 状态栏支持单人角色卡和世界/旁白卡，群聊场景卡不能带状态栏；插件内的「试聊」不显示状态栏，也不更新变量。状态栏只显示变量，不能在界面上反过来修改变量。
- 立绘图片由玩家的浏览器直接从图床加载（不带来源页），图床禁止外链或地址失效时只显示首字占位；手动选的图只记在当前浏览器里，换浏览器或清理站点数据后回到默认那张。
- 状态栏卡依赖网络上的 MVU 与 mvu_zod 脚本（默认 testingcf.jsdelivr.net，不固定版本，可在设置里改地址）；它们更新后行为可能变化，已验证的版本见「状态栏 / MVU 变量」一节。
- 酒馆助手「角色脚本」的启用状态存在酒馆助手自己的设置里，NovelLoom 读不到，只能提示；本卡正则是否已允许可以检测。
- 「最新 N 层」只对之后渲染的楼层生效：已经显示出来的旧楼层，要重新打开聊天后才会隐藏状态栏。
- 自定义 HTML 模式下 NovelLoom 不注入运行时，界面里的脚本需要自己读取 `stat_data`；这类界面的危险写法（网络请求、访问上层页面等）只提示不阻止，请只粘贴来源可信的代码。
- 「推演当前对话」只支持单人角色对话，群聊（多角色、没有固定的单一角色卡）暂不支持；结果存在这个对话自己的聊天数据里，删除/导出这个对话时会跟着一起走，不会同步到角色卡本身，也不会跟角色卡页的「剧情推演」互相同步。
